## 이번 구현

- 회원·보호소 / 동물·입양 / 커뮤니티 / 봉사·후원 / 문의·신고 / 마케팅·알림 / 안전과 운영: 25개 기능을 빠짐없이 7개 묶음에 배치.
- 현재 업무 묶음만 기본으로 펼치고, 메뉴를 검색하면 일치하는 묶음을 펼친다. 권한이 없는 업무는 기존 서버 접근 제어와 UI 필터를 유지한다.
- 운영 요약에서 대기 업무와 전체 기록을 분리. 대기 업무는 확인 실패, 건수 많은 순으로 배치한다. 이는 긴급도 점수가 아니라 표시 순서다.
- 대기 카드→목록 이동 시 동일한 pending 상태 집합으로 데이터베이스에서 필터링한다. 페이지네이션과 total도 같은 조건을 사용한다.
- 전체 상태/처리 대기 전환과 검색 초기화. 업무를 바꾸면 이전 업무의 역할·공개 여부·검색 조건이 섞이지 않도록 초기화한다.
- SEED SideNavigationGroup의 접이식 패턴, TextField, ActionButton, Callout, Badge와 기존 semantic token을 사용한다. Tabler CSS/Bootstrap, 새 관리자 엔진, TDS 토큰은 추가하지 않았다.

## 운영에 필요한 기능의 현재 상태와 후속 작업

| 업무 | 현재 구현 | 남은 기능 / 이유 / 진행 방법 |
| --- | --- | --- |
| 회원·보호소 | 회원 역할·로그인 수단 확인, 프로필 수정, 제재, 세션 해제, 보호소 수정·인증 | 대상별 활동·조치 타임라인: 기록을 개별 회원/콘텐츠와 연결하는 조회 API 필요. 역할 변경은 권한 상승 방지 절차와 감사 기록까지 함께 구현해야 함 |
| 동물·입양 | 직접 등록 심사, 입양 신청 상담·상태 처리, 인증·돌봄 위기 | 공공동물 전용 관리 목록 및 사진·공고번호 탐색: 공공 데이터는 원본 소유권과 동기화 정책이 달라 별도 읽기 목록부터 추가해야 함. 진료·예약·보호소 재고는 우리 플랫폼의 현재 업무 범위에 포함하지 않음 |
| 커뮤니티·신고 | 글·질문·답변·그림·소식 수정/숨김, 신고 처리, 이의제기 | 신고 대상 본문과 과거 조치 이력을 같은 상세에 표시. 운영자 내부 메모는 저장 테이블·서버 권한·감사가 필요 |
| 고객 문의 | 문의 접수·답변·앱 알림 | 담당자 배정, 내부 메모, 응답 기한: 담당자/기한 필드와 상태 정책, 알림 처리 필요. 현재 생성일을 SLA 기한으로 가장하지 않음 |
| 마케팅 | 초안, 동의 회원 대상 큐, 수동 발송, 기록·해지 | 실제 이메일은 RESEND_API_KEY/EMAIL_FROM/EMAIL_REPLY_TO 및 발신 도메인 인증 필요. 반송·도착 웹훅과 예약 발송 작업은 별도 구현해야 함 |
| 봉사·후원 | 공고·신청 처리, 후원·모금 의향 기록 | 후원 의향은 결제 실적이 아님. 결제·환불·정산은 PG 계약과 웹훅·회계 기준이 있어야 구현 가능 |
| 운영 기록·연결 | 감사 기록, 동기화 상태, 로그인 키 등록 상태 | 로그인 설정 유무는 실계정 로그인 성공 보증이 아님. 백업 복구 훈련, 장애 알림, 대상별 감사 조회가 남음 |

이번 작업은 위 사례에서 확인한 탐색·대기 처리 패턴을 실제 API에 연결한 개선이다. 후속 항목을 동작하는 것처럼 버튼만 추가하지 않았다. 구현 범위와 외부 연동 제한은 [기존 운영 관리 기록](OPERATIONS_MANAGEMENT_2026-09-07.md)과 함께 확인한다.
