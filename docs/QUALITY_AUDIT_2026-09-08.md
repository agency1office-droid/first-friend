# 웹사이트 안정성 점검 — 2026-09-08

기준: `d0f7678`. 3개 에이전트와 메인 작업자가 화면, 인증/API, 관심 친구, 목록 복원을 나누어 검사했다. 운영 데이터는 수정하지 않았다. 이번 변경은 로컬이며 배포하지 않았다.

## 확인하고 수정한 문제

| 영역 | 문제와 수정 |
| --- | --- |
| 봉사·후원 의향 | 연속 클릭이 여러 요청을 만들고 네트워크 실패 후 안내가 없었다. 즉시 잠금, 처리 표시, 실패 안내와 재시도를 추가했다. |
| 사진 갤러리 | 방향키가 사진 요소와 window에서 각각 처리돼 한 번에 두 장 넘어갔다. 이미 처리한 이벤트를 제외한다. |
| 동네 설정 | 늦게 도착한 IP·프로필·동네 조회가 새 수동 선택을 덮어썼다. 최신 선택의 응답만 적용하고 화면을 떠나면 중단한다. |
| 목록 복구 | 최초 조회 실패에 '다음 페이지'를 요청해 재시도가 작동하지 않았다. 실패한 종류에 맞게 첫 페이지 또는 추가 페이지를 재시도한다. |
| 목록 경쟁 요청 | 연속 추가 조회와 필터 변경 전 응답이 간섭할 수 있었다. 중복 추가 조회를 막고 이전 조건의 요청·응답을 폐기한다. |
| 관심 친구 | 조회 실패나 공고 조회 불가를 스크랩 없음으로 표현했다. 오류와 보관 중인 기록을 구분한다. |
| 계정 변경 | 이전 계정의 늦은 스크랩 응답이 현재 계정의 표시·로그인 이동에 영향을 줄 수 있었다. 계정 범위가 다르면 적용하지 않는다. |
| 지역 저장 API | DB 저장 실패에도 성공을 반환했다. 실패를 503으로 반환한다. |
| 저장 검색 | API와 화면의 필드 이름이 달라 알림 상태와 조건이 잘못 표시됐다. 응답 계약을 맞추고 잘못된 입력·DB 오류를 구분한다. |
| 검색 알림 | 잘못된 검색 조건 하나가 전체 알림 조회를 중단시켰다. 저장 시 타입을 검증하고 기존 비정상 조건은 건너뛴다. |

## 검증 범위

- 운영 사이트의 홈, 이야기, 함께하기, 보호소, 입양 준비, 안내, 실종·발견, 질문, 마이페이지, 관리자 진입을 모바일 폭 390px에서 읽기 전용 확인: 가로 넘침·브라우저 실행 오류 없음. 비로그인 관리자 진입은 로그인으로 이동.
- 신규 회귀 검사: `auth-audit`, `favorites-audit`, `client-action-state`, `feed-recovery`. 실제 소스에 오류·지연·계정 변경·중복 요청을 주입한다.
- 전체 `npm run lint` 통과, `npm test` 빌드와 112개 검사 모두 통과.
- 빌드된 앱의 브라우저 검증 통과: 홈 → 관심 친구 → 홈 이동의 문서 요청 1회, 목록·위치 조회 각 1회, 스크롤 복원, 만료된 목록 갱신 실패 시 기존 카드 유지, 재시도 시 문서 새로고침 없이 복구.

## 남은 제한

- 보호소 소식 응원(`/api/shelter-reactions`)은 반응 기록과 집계를 별도 요청으로 변경한다. 동시 요청·중간 실패 때 일치하지 않을 수 있다. DB 트랜잭션/RPC로 둘을 함께 변경하고 재시도 시 원하는 상태를 명시하는 개선이 필요하다. 이번 변경에는 포함하지 않았다.
- 동네 선택은 기기 공용 localStorage를 사용한다. 계정별 동네 정책과 저장소 차단 환경은 추가 점검 대상이다.
- 과거 관심 친구 기록 삭제의 실행 주체·시각은 이번 수정으로 입증되지 않는다.
- 실제 OAuth 본인 로그인, 실제 후원·봉사 접수 등 운영 데이터를 바꾸는 테스트는 수행하지 않았다. 이번 점검이 모든 경로의 무결함이나 보안 보증을 의미하지 않는다.
