# 전체 사이트 기능·보안 점검 — 2026-09-07

포니테일 기준으로 app/lib/tests의 247개 파일 구성을 조사하고, 공통 함수·상태 저장·인증·미디어·DB 경계를 먼저 점검했다. 이후 인증/보안, 업무 API, 공개 UI를 3개 에이전트에 나눠 맡겼다. 두 에이전트는 사용량 제한으로 중단되어 주 에이전트가 남은 변경·SQL·검증을 직접 통합했다. 이 보고서는 발견한 문제와 확인 범위를 기록하며, 모든 취약점이 없다는 보증은 아니다.

## 수정한 문제

| 영역 | 확인한 문제 | 수정 |
|---|---|---|
| 단순화 | 임의 동물 ID 조회 실패까지 Map에 무제한 저장 | 불필요한 fallback 캐시 제거, 작은 기존 배열 조회 사용 |
| 요청 제한 | DB 오류 때 제한 없이 허용; 짧은 제한 창이 다른 업무의 긴 창 기록까지 삭제 | 실패 시 차단, scope별 정리 |
| 직접 DB 접근 | 요청 제한 기록의 익명 조회 가능; 업무 테이블 권한 정책이 저장소에서 일관되지 않음 | 업무 테이블 RLS 및 anon/authenticated 권한 회수. 서버 service_role API는 유지 |
| 동물 숨김 | 원본 REST 직접 접근에는 hidden 조건 없음 | 공개 RLS에 hidden 제외 조건 추가 |
| 인증 | 교차 출처 가입/로그인, 과도한 입력, 제재 회원 비밀번호 세션 발급 | 출처·입력·제재 검증, 실패한 가입의 신규 회원 정리 |
| 이미지 프록시 | 허용 URL 뒤의 외부 리다이렉트를 따라감 | 리다이렉트·임의 포트·URL 인증정보 거부 |
| 업로드 | 앞 64바이트만 중복 판별, 공개/증빙 용도 미구분 | 전체 SHA-256과 용도 포함, 허용 용도 검증 |
| 증빙 | 이의제기 업로드 경로와 제출/심사 경로 불일치 | appeal-evidence 경로로 통일, 제한·출처 검사 |
| 동물·입양 | 소유자가 직접 공개하거나 종료 신청을 다시 승인/철회/인계 | 운영 심사 경계와 현재 상태 조건 적용 |
| 보호소 | 담당자가 없는 공공 보호소를 임의로 연결; 다른 보호소 이름 선택 | 운영자 연결과 소유권 검사 |
| 게시물·그림 | 다른 회원/비공개 증빙 파일을 공개 이미지로 연결 | 본인의 공개 업로드 경로만 허용 |
| 실패 응답 | 관심 친구·신고 저장 실패에도 성공처럼 응답 | 실패 상태 반환 |
| 봉사 | 보호소 API에서 정원 초과와 완료 상태 재변경 가능 | 관리 API와 같은 모집 행 잠금, 트랜잭션·권한·상태 검사 |
| 관심 친구 | 일부 초기값을 전체 캐시로 간주; 네트워크 오류 뒤 버튼 잠김 | 초기값/전체 목록 분리, 중복 클릭 잠금과 finally 복구 |
| 찾기 | 조건 검색이 필터를 잃고 그림 결과로 이동 | 조건 화면에서 결과 표시, 품종/종 검색 반영 |
| 화면 생명주기 | useEffect가 Promise를 정리 함수처럼 반환 | effect는 void 반환, 필요한 의존성 유지 |
| 폼 저장 | await 이후 currentTarget이 사라져 성공 후 초기화 실패 | 이벤트 처리 시작 시 form 요소 보존 |

새 프레임워크나 런타임 UI 라이브러리는 추가하지 않았다. 기존 SEED와 화면 구조를 유지했고 TDS는 추가 참고하지 않았다.

- [Vite Windows 파일 접근 우회 공지](https://github.com/advisories/GHSA-fx2h-pf6j-xcff), [fflate 수정 공지](https://github.com/advisories/GHSA-px8p-9vwx-vf98)를 확인했다.
- 남은 항목: Cloudflare/miniflare/wrangler/undici/ws/sharp 계열, vinext/image-size, transformers, drizzle-kit/esbuild 계열. 버전 강제 교체는 하지 않았다. 프레임워크·모델 로딩·빌드 호환성 검증을 포함한 별도 업그레이드가 필요하다. 실제 외부 입력의 도달 가능성은 항목별로 추가 평가해야 한다.

## 검증과 범위

- 필수 `npm run lint`, `npm test`: 빌드와 기존 OAuth·운영 검사에 새 인증·업무·UI 회귀 검사를 추가했다.
- 실제 PostgreSQL 엔진(PGlite)에서 권한 회수, 긴/짧은 요청 제한 창 간섭, 소유권, 봉사 정원·상태·감사 실패 롤백을 검사한다. 운영 데이터에 공격용 자료를 넣지 않는다.
- 브라우저의 테스트 데이터 기반 관리자 목록·상세·모바일 검사와 공개 URL/보안 응답 검사를 구분한다.
- `.env`, 비밀키·회원 데이터는 보고서나 커밋에 포함하지 않는다. 운영 익명 DB 검사는 HEAD로 상태·건수만 확인했다.

## 남은 문제와 다음 작업

1. 제재 회원 전용 이의제기 인증 경로: 일반 세션 차단을 유지하면서 이의제기만 가능한 별도 흐름이 필요하다.
2. 비밀번호 이메일 인증·마케팅 이메일 실제 수신: 발신 서비스 설정과 발신 도메인 인증 후 실제 수신 검증이 필요하다.
3. 일부 입양·인계·알림·투표의 여러 단계 DB 처리: 완전한 트랜잭션 이전이 아직 남았다. 부분 성공과 동시 요청 회귀 검사가 필요하다.
4. 이상형 월드컵: 현재 정적 성향 선택 흐름이며 실제 동물 DB 대진표 기능은 별도 구현해야 한다. 이번 보안 수정에서 기능이 완성됐다고 간주하지 않는다.
5. 실제 소셜 제공자 본인 로그인부터 운영 조치까지: 일반 Chrome에서 본인 인증과 허가된 테스트 자료가 필요하다. 자동 테스트 통과는 이 검증을 대체하지 않는다.
6. 공개 이야기의 기존 샘플과 일부 외부 서비스 더미는 유지했다. 실제 결제·전송 계약이 없는 기능을 새 외부 서비스로 연결하지 않았다.
