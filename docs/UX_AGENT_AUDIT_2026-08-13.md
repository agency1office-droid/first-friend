# 퍼스트 프렌드 이용자 감사 및 개선 기록

점검 기준일: 2026-08-13

## 점검 방식

공개 배포 사이트와 로컬 프로덕션 빌드를 실제 이용자처럼 탐색했다. 보호동물 탐색, 검색 방법 선택, 동물 상세, 실종·발견, 이야기, 입양 준비도, 봉사·후원, 로그인 진입을 확인하고 다음 관점으로 나누어 판단했다.

## 에이전트별 결과

### 1. 첫 방문자

긍정:

- 지역·거리 중심의 첫 화면이 서비스 목적을 빠르게 설명한다.
- 하단 내비게이션이 홈·관심 친구·이야기·함께하기·나의 페이지로 단순하다.
- 개인정보와 위치 공개 범위에 대한 설명이 친절하다.

부정 및 부족:

- 첫 API 요청이 끝나기 전 `0마리` 빈 상태가 먼저 보이면 서비스가 비어 있다고 오해할 수 있다.
- 입양을 시작하는 대표 행동과 검색 방법 선택의 관계가 처음에는 약하다.

개선:

- 데이터 로딩 중에는 빈 상태 대신 로딩 스켈레톤을 표시한다.
- 최신 동기화 시각과 지연 여부를 목록 위에 표시한다.
- 데이터 연결 실패와 실제 검색 결과 없음 상태를 분리한다.

### 2. 입양 희망자

긍정:

- 동물 상세에 공공데이터 출처, 보호 상태, 갱신일, 보호소 연락처가 있다.
- 준비도·비용·생활 환경을 입양 전 과정과 연결하려는 방향이 좋다.
- 준비도 결과를 자동 탈락 기준으로 사용하지 않는다고 명시한다.

부정 및 부족:

- 동물 상세의 핵심 CTA가 전화 중심이라 상담·신청·답변 상태를 플랫폼 안에서 이어가기 어렵다.
- 공공데이터의 건강·성격 공백이 많아 첫 만남 전에 무엇을 물어볼지 더 구조화할 필요가 있다.

개선 우선순위:

1. 상담 시작 → 질문 목록 → 보호소 답변 → 방문 일정의 상태 흐름
2. 동물별 최신 확인 시각과 정보 신뢰 수준
3. 관심 동물 상태 변경·검색 조건 알림

### 3. 보호소 운영자

긍정:

- 운영 콘솔, 인증, 봉사, 필요 물품, 후원 기록을 고려하고 있다.
- 보호소가 입양 승인과 의료 판단의 최종 주체임을 명확히 구분한다.

부정 및 부족:

- 데이터 최신성 관리와 문의 응답을 보호소가 얼마나 쉽게 처리하는지는 아직 핵심 화면에서 보이지 않는다.
- 운영 기능이 많지만 실제 운영자가 매일 쓰는 최소 작업 흐름을 먼저 좁힐 필요가 있다.

개선 우선순위:

- 오늘 확인할 문의
- 상태 변경이 필요한 동물
- 오래된 공고
- 봉사 모집
- 필요 물품

### 4. 임시보호자·봉사자

긍정:

- 청소·사진·이동·의료·돌봄처럼 봉사를 유형으로 나눈 점이 좋다.
- 임시보호 등록과 인증 구조가 있어 장기 확장성이 있다.

부정 및 부족:

- 공고가 없을 때 다음 행동이 약하다.
- 입양으로 바로 결정하기 어려운 사용자를 단기 봉사 → 임시보호 → 입양으로 안내하는 단계가 더 선명해야 한다.

### 5. 커뮤니티 이용자

긍정:

- 별점·댓글 경쟁 대신 공감·응원 중심의 분위기가 보호동물 주제와 잘 맞는다.
- 정확한 구조 위치, 급식 장소, 개인 연락처를 공개하지 않는 원칙이 좋다.

부정 및 부족:

- 초기 커뮤니티에서 응원 숫자가 실제 참여보다 앞서 보이면 신뢰가 떨어질 수 있다.
- 이야기와 입양 전환의 연결이 약하다.

### 6. 신뢰·안전 담당자

긍정:

- 사진 처리, 위치 비공개, 보호소 인증, 신고·이의제기, 모금 승인 원칙이 있다.
- AI가 건강·성격·입양 성공을 판단하지 않는다는 한계 고지가 있다.

부정 및 부족:

- 오래된 공고, 중복 동물, 정보 불일치를 이용자가 신고하고 수정 요청하는 경로를 더 잘 보여줘야 한다.
- 외부 전화 상담으로 빠져나간 뒤 기록이 끊기는 점이 분쟁 추적성을 낮춘다.

## 사용 중 발견한 핵심 문제

### P0 — 로딩과 빈 상태가 섞임

초기 요청 중에도 빈 결과 메시지가 표시될 수 있었다. 실제 데이터가 없다는 뜻과 아직 확인 중이라는 뜻이 달라야 한다.

### P0 — 오류 재시도 버튼이 빈 목록에서 동작하지 않음

목록이 비어 있는 상태에서 오류가 나면 기존 재시도 버튼이 다음 페이지 로딩 함수만 호출해 실제 첫 요청을 재시도하지 못했다.

### P1 — 검색 조건 URL 동기화 누락

나이·크기 조건은 읽을 수 있지만 URL을 다시 만들 때 저장되지 않아 공유·새로고침 시 조건이 사라질 수 있었다.

### P1 — 상세에서 상담 상태가 단절됨

전화는 빠르지만 문의 내용·응답·방문 일정·상태 변경이 서비스 밖으로 빠져나간다.

## 이번 작업에 반영한 개선

- `HomeAnimalFeed`에 로딩 스켈레톤과 상태 안내 추가
- 최신 동기화 시각 및 지연 데이터 안내 추가
- 오류 상태와 실제 빈 결과 상태 분리
- 빈 목록에서도 첫 페이지를 다시 요청하는 재시도 함수 추가
- 나이·크기 검색 조건의 URL 보존 수정
- 빈 결과 문구에 전국 검색·알림으로 이어질 다음 행동을 추가

## 다음 구현 권장 순서

1. 동물 상세 상담을 플랫폼 내 대화·상태 흐름으로 연결
2. 검색 조건 저장과 새 동물·상태 변경 알림 완성
3. 보호소 운영 콘솔을 문의·오래된 공고·상태 변경 중심으로 단순화
4. 임시보호를 입양 전 단계로 설계
5. 데이터 품질 지표와 사용자 수정 요청을 공개
