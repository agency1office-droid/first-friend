# 운영 관측성 기준

현재 운영 배포는 Vercel 로그를 기본 관측 채널로 사용합니다. API 오류와 핵심 작업 실패는 JSON 한 줄 로그로 기록하며, `type`, `event`, `at`, `requestId`를 기준으로 검색할 수 있습니다.

## 이벤트 규칙

- 사용자 개인정보, 인증 토큰, 쿠키, 전화번호, 이메일 주소는 로그에 기록하지 않습니다.
- 동물 ID처럼 운영 추적에 필요한 식별자는 오류 원인 분석에만 제한적으로 기록합니다.
- 이벤트 이름은 `영역.동작_결과` 형태를 사용합니다. 예: `sync.public_animals_failed`.
- 외부 Sentry/PostHog 연결 전에도 동일한 구조를 유지해 로그 기반 장애 대응이 가능합니다.

## 연결 순서

1. Vercel Production에서 Vercel Logs로 오류 이벤트와 요청 ID를 확인합니다.
2. Sentry를 연결할 때는 이 모듈의 `logError` 호출 지점을 Sentry capture adapter로 교체합니다.
3. PostHog를 연결할 때는 `logEvent` 이벤트 이름을 그대로 제품 분석 이벤트로 매핑합니다.

외부 플러그인이나 API 키가 연결되기 전에는 애플리케이션이 임의로 외부 서비스로 데이터를 전송하지 않습니다. 따라서 현재 변경에는 비밀키나 외부 전송 설정이 포함되지 않습니다.
