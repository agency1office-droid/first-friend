# 회원 이야기 게시판

비마이펫 라운지의 간결한 목록을 참고하고 기존 SEED UI·회원 세션·Supabase를 사용한다. 별도 게시판 엔진이나 에디터 패키지는 추가하지 않았다.

## 화면

- `/stories`: 실제 회원 글, 작성자, 제목 검색, 분류, 최신순/반응순, 20개씩 페이지 이동. 사진은 대표 썸네일 1장과 첨부 수만 표시한다. 목록에는 가장 많이 남긴 반응 아이콘 3개와 총합을 보여 준다.
- `/stories/new`: 회원 전용 작성. 제목 80자·본문 2,000자, 일반 텍스트, 사진 3장. 임시저장은 사용자가 누르는 방식이다.
- `/stories/manage`, `/stories/manage/[id]`: 내 글 상태, 이어 쓰기, 수정, 확인 후 삭제.
- `/stories/post-[id]`: 글과 사진 갤러리, 다섯 가지 반응(응원해요·감동이에요·귀여워요·고마워요·슬퍼요), 공유, 신고. 회원은 글마다 반응 하나만 남기고 바꾸거나 지울 수 있다. 글마다 처음 남긴 반응은 작성자 알림함(`story_reaction`)에 알린다. 반응 아이콘은 Tossface SVG(`public/reactions/`)를 그대로 쓴다.
- 관리자 이야기 관리: 게시 상태·응원 수·사진 확인, 공개 글 수정/숨김 및 기존 감사 기록.

## 저장과 권한

사진은 장당 4MB 이하 JPEG/PNG/WEBP만 받는다. Vercel 요청 크기 제한 내에서 처리하도록 4MB로 제한한다. 서버에서 실제 이미지를 디코딩하고 방향 보정 후 EXIF 없이 최대 1,200px WebP와 320px 썸네일로 저장한다.

`story-media`는 비공개 버킷이다. 게시 중이며 숨겨지지 않은 글에 첨부된 사진만 공개 API에서 제공한다. 그 외 사진은 작성자와 운영자만 조회할 수 있다. 일반 회원은 다른 회원의 임시저장 글을 읽거나 수정할 수 없다. 운영자는 기존 관리 API에서 검토할 수 있다.

글 수정·삭제는 소유권과 revision을 확인한다. 운영자 수정/숨김도 DB 트리거에서 revision을 증가시켜 오래된 작성 화면의 덮어쓰기를 막는다. 반응은 행 잠금 RPC로 원자적으로 설정하며 감정별 수(`reaction_counts`)와 총합(`reaction_count`)을 함께 증감한다. 같은 요청을 반복해도 수가 늘지 않는다. 신규 글은 작성자/client_key 고유 제약으로 중복 생성을 막는다.

공개 글의 개인정보 패턴 검사는 일부 연락처·주소 패턴에 대한 보조 수단이다. 모든 개인정보나 사진 내용을 자동 판별하는 기능은 아니므로 신고·운영 검토를 함께 사용한다.

## DB 적용

순서:
1. `20260908000400_story_board.sql`
2. `20260908000500_story_revision.sql`
3. `20260912000100_story_reactions.sql`

기존 글은 공개 상태와 기존 사진을 유지한다. 삭제는 소프트 삭제다. 새 글의 사진과 달리 기존 public-media 사진의 공개 URL은 이번 변경으로 소급 비공개 전환하지 않는다.

## 검증

- `npm run lint`, `npm run typecheck`, `npm test`.
- `tests/story-board.test.mjs`: 비회원 작성, 타인 수정, 타인 사진 사용, 비공개 접근, 사진 수 제한, 리사이징/EXIF 제거, 중복 생성, 수정 충돌, 숨김·삭제 후 비공개, 장애 응답.
- `tests/story-reactions.test.mjs`: 비회원·다른 출처 차단, 허용되지 않은 반응 거부, 반응 변경·삭제, 작성자 알림 1회, 본인 글 알림 제외, RPC 실패 응답.
- PostgreSQL 호환 엔진에서 migration/RPC/트리거, 중복 응원, 익명 역할 차단을 별도 실행 검증.
- 실제 Supabase에 일회용 회원·비공개 초안·사진으로 저장/수정/삭제와 접근 제한을 검증한 뒤 테스트 데이터를 정리.
- 브라우저에서 모바일/데스크톱 목록, 사진 3장, 임시저장, 게시 이동, 일반 텍스트 이스케이프, 응원, 신고, 삭제 확인을 검증.

## 보관 및 범위

글에서 제거했거나 게시하지 않은 사진도 비공개 저장소에 남는다. 자동 영구 삭제 작업은 아직 없으며, 보관 기간 정책을 정한 뒤 연결되지 않은 오래된 파일 정리를 추가할 수 있다. 소프트 삭제된 글도 DB에 보관된다.

댓글·구독·리치 텍스트·자동 임시저장·사진 내용 자동 심사는 이번 범위에 포함하지 않는다.
