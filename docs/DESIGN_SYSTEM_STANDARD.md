# 퍼스트프렌드 디자인 시스템 기준

이 문서는 퍼스트프렌드 UI의 상시 검수 기준이다. 구현 우선순위는 다음과 같다.

1. SEED Foundations
2. SEED Components와 설치된 패키지의 실제 recipe
3. SEED Patterns
4. SEED에 적절한 패턴이 없을 때는 로컬에 보관한 Toss TDS 레퍼런스를 먼저 검토한다. 적용할 때도 색상·타이포그래피·간격·아이콘 토큰은 SEED를 기본으로 유지하고, TDS의 정보 구조·상태 표현·행동 우선순위만 보조 기준으로 사용한다.

토스 TDS 레퍼런스: `D:\\codex\\first-friend\\.codex-local\\design-references\\toss-tds` (v2.5.1)

기준 문서: https://seed-design.io/foundations

## Foundations 적용 원칙

### Design Token

- raw 값보다 semantic token을 먼저 사용한다.
- 색상, 타이포그래피, 간격, radius, elevation, motion을 임의 px·hex 값으로 추가하지 않는다.
- 화면 좌우 여백은 `global-gutter`를 기준으로 한다.

### Color

- 역할 기반 색상(`fg`, `bg`, `stroke`)을 사용한다.
- 브랜드색은 주요 행동, 선택 상태, 핵심 피드백에만 사용한다.
- 단순 장식이나 모든 기본 선택 항목에 브랜드색을 반복하지 않는다.
- 상태는 색상만으로 전달하지 않고 텍스트, 아이콘, 형태를 함께 사용한다.

### Typography

- SEED 시스템 폰트 스택을 사용한다.
- 폰트 크기와 줄 높이는 같은 단계의 토큰을 짝지어 사용한다.
- 본문은 주로 t1-t5, 제목은 t6-t10을 사용한다.
- t11-t14는 `sm` 이상 큰 화면에서만 사용한다.
- 화면 제목과 콘텐츠 본문은 가능한 경우 semantic text style을 우선한다.
- 고정 px 대신 상대 단위 기반 SEED 토큰을 사용해 사용자 폰트 크기 설정을 존중한다.

### Iconography

- 직접 그린 SVG보다 SEED 아이콘 라이브러리를 먼저 사용한다.
- 의미가 명확한 모노크롬 아이콘을 기본으로 하고, 멀티컬러 아이콘은 설명적·감성적 맥락에 제한한다.
- 아이콘 단독 버튼에는 접근 가능한 이름을 제공한다.

### Elevation

- elevation은 실제 레이어 관계를 설명할 때만 사용한다.
- 카드 구분을 위해 무분별한 그림자를 사용하지 않는다.
- 고정 내비게이션, 시트, 다이얼로그, 플로팅 액션처럼 겹침 관계가 있는 요소에만 정해진 토큰을 적용한다.

### Gradient

- 정보 계층이나 브랜드 표현에 명확한 목적이 있을 때만 사용한다.
- 기본 카드와 목록의 장식용 그라데이션은 사용하지 않는다.

### Inclusive Design

- 키보드, 스크린리더, 확대, 색각 차이를 고려한다.
- 터치 목표는 최소 44px 이상을 확보한다.
- 포커스, 선택, 오류, 비활성 상태를 시각적·의미적으로 구분한다.
- 애니메이션 감소 환경을 지원한다.

### International Design

- 날짜, 시간, 거리, 통화, 숫자는 로케일 포매터를 통해 표시한다.
- 한국어 외 언어에서 늘어나는 텍스트 길이를 고려해 고정폭을 피하고 줄바꿈을 허용한다.
- 동네명, 보호소명, 품종명처럼 길이가 변하는 데이터는 말줄임과 전체 정보 접근 방법을 함께 제공한다.

### Layout

- Mobile First로 설계한다.
- base/sm은 16px gutter와 12px margin, md 이상은 32px gutter와 24px margin을 기준으로 검토한다.
- 정보 중심 화면은 Content Layout, 관리자 화면은 Dashboard Layout을 사용한다.
- 모바일에서는 사이드 내비게이션을 상단 메뉴 또는 시트로 통합한다.

### Motion

- 버튼, 포커스 등 마이크로 모션은 0.2초 이하로 유지한다.
- 시트와 다이얼로그는 SEED enter/exit timing token을 사용한다.
- 기능을 설명하지 않는 과도한 모션은 추가하지 않는다.

### Radius

- 컴포넌트 recipe가 정의한 radius를 그대로 사용한다.
- 페이지 전체나 큰 콘텐츠 영역을 임의의 둥근 카드로 감싸지 않는다.
- 이미지, 아이콘 컨테이너, 시트처럼 역할이 분명한 요소에만 radius를 적용한다.

### Spacing

- SEED spacing scale만 사용한다.
- 화면 좌우 gutter, 섹션 간격, 컴포넌트 내부 간격을 구분한다.
- 인접 요소를 임의의 작은 간격으로 붙이지 않고, 컴포넌트 recipe의 padding을 우선한다.

### State

- default, pressed, focused, selected, disabled, loading, error 상태를 구현한다.
- 선택 상태는 브랜드색만이 아니라 배경, 테두리, 체크, 레이블 등 해당 SEED recipe를 따른다.
- 비활성 요소를 단순히 opacity만 낮추지 않고 의미와 조작 가능 여부를 함께 전달한다.

### Voice and Tone

- 친근하고 직접적이며 판단하지 않는 문장을 사용한다.
- 보호자, 입양자, 보호소를 비난하거나 불안을 과장하지 않는다.
- 사용자가 다음 행동을 바로 이해할 수 있는 표현을 우선한다.

### 퍼스트프렌드 공통 문체 가이드

모든 화면 문구, 버튼 레이블, 안내·오류 메시지, AI 생성 프롬프트와 결과 문구에 아래 기준을 적용한다. 당근의 친근함과 토스의 간결함은 참고하되, 브랜드 문구를 그대로 모방하지 않고 퍼스트프렌드만의 따뜻하고 담백한 ‘친구를 소개하는 말투’로 작성한다.

- 사용자를 존중하는 친근한 존댓말을 사용한다. 가능한 경우 `~해요`로 자연스럽게 끝맺는다.
- 짧고 자연스러운 문장으로 작성하고, 사용자가 빠르게 이해하도록 핵심과 다음 행동을 먼저 전달한다.
- 단순히 기능이나 내용을 설명하는 데 그치지 않고, 사용자가 무엇을 얻는지 알 수 있도록 이점과 도움이 되는 점을 먼저 전달한다. 예: `입양 전 필요한 내용을 확인해 보세요.`보다 `함께할 준비가 되었는지 확인해 보세요.`처럼 쓴다.
- 어려운 전문용어, 내부 용어, 행정·보고서식 표현은 생활 언어로 바꾼다.
- 과도하게 귀엽거나 감정적인 표현, 과장된 감탄사, 동정심을 유도하는 표현을 사용하지 않는다.
- 동물을 불쌍하게 묘사하거나, 확인되지 않은 건강·성격·품종·행동·입양 가능성을 사실처럼 단정하지 않는다.
- AI가 추정한 내용은 추정임을 분명히 밝히고, 건강·성격·입양 가능 여부는 보호소 확인이 필요하다고 안내한다.
- 권장 표현은 `이 친구를 소개할게요`, `사진에서는 이렇게 보여요`, `~처럼 보여요`, `~한 모습이에요`처럼 관찰과 인상을 구분하는 표현이다.
- 매력을 소개할 때는 사진에서 확인할 수 있는 귀엽고 예쁘고 인상적인 모습을 구체적으로 짚되, 근거 없는 성격 칭찬이나 감정 투사는 피한다.
- 버튼은 행동을 나타내는 짧은 동사형으로 작성한다. 예: `시작하기`, `다음`, `다시 확인하기`.
- 오류·실패 안내는 사용자를 탓하지 않고 문제, 필요한 조치, 다음 방법 순서로 안내한다.
- 문구를 추가하거나 수정할 때는 주변 화면의 말투와 정보 위계를 함께 확인해 한 화면 안에서 일관되게 유지한다.

### Writing

- 결론과 사용자가 할 일을 먼저 쓴다.
- 내부 용어와 행정 용어를 그대로 노출하지 않고 생활 언어로 번역한다.
- 버튼은 행동을 나타내는 동사형으로 작성한다.
- 오류 메시지는 문제, 원인, 해결 방법 순으로 안내한다.

## 요청별 디자인 검토 순서

1. 현재 화면과 설치된 SEED recipe를 먼저 확인한다.
2. SEED에 같은 목적의 컴포넌트나 패턴이 있으면 SEED를 그대로 사용한다.
3. SEED에 없거나 정보 위계가 약하면 로컬 TDS 레퍼런스에서 Badge, Button, Banner, CTA, 상태 표현을 비교한다.
4. 최종 구현은 하나의 화면 안에서 SEED 토큰과 접근성 기준으로 통합하며, 두 시스템의 시각 토큰을 임의로 섞지 않는다.
