# 운영 콘솔 연결 점검 — 2026-09-07

UI, API·권한, 공개 서비스 연결을 3개 에이전트가 나눠 점검하고 통합했다. Tabler식 전체 폭 레이아웃과 기존 SEED 컴포넌트·토큰을 유지했다. TDS를 새로 참고하거나 UI 프레임워크를 추가하지 않았다.

## 수정한 연결

- 27개 관리 목록: 보호소 필요 물품 조회 추가. 물품 수량 수정은 기존 보호소 관리 흐름을 사용하며 운영 콘솔에서는 조회 전용이다.
- 신청 회원·심사 증빙·대표자·사업자/면허 번호·보호처 연락처·그림/실종 사진·감사 기록을 상세 검토에 연결했다.
- 봉사 신청 버튼은 실제 허용되는 상태 변경만 표시한다. 정원과 완료 배지는 SQL에서 검사한다.
- 동물 등록, 역할 인증, 외부 입양 인증, 이의제기, 모금 심사는 `review_operation`에서 상태·관련 회원 변경·알림·감사 기록을 한 트랜잭션으로 처리한다.
- 운영자 권한을 SQL에서 다시 검사하고, 과거 역할 인증 신청으로 관리자 역할을 덮어쓰지 못하게 했다.
- 직접 등록 동물의 공개 상세·관심 친구·입양 신청 조회를 연결했다. 비공개·재확인 만료 동물은 제외한다.
- 새 입양 신청에 직접 등록자 또는 연결된 인증 보호소 담당자를 저장한다. 운영 DB에 기존 신청은 없었고, 과거 데이터 자동 이관은 하지 않는다.
- 사진/조건 찾기와 사이트맵은 숨김이 적용된 DB 목록을 사용한다. 동물 목록 HTTP 캐시와 서버의 완료 결과 캐시를 제거해 새 요청에서 공개 상태를 다시 확인한다.
- Node 운영 환경에서도 실제 이야기 DB를 조회한다. 보호소 본문 이름·지역은 운영 프로필 변경값을 반영한다.

## 검증 범위

- 필수 검사: `npm run lint`, `npm test` (빌드, 권한, OAuth, 운영 API, 공개 연결 회귀 테스트).
- 실제 PostgreSQL 엔진을 사용하는 격리 PGlite: `tests/operations-management.sql`, `tests/animal-management.sql`, `tests/operations-volunteer.sql`, `tests/operations-review.sql`. 운영 DB에 테스트 회원이나 제재를 생성하지 않는다.
- Chrome의 테스트 데이터 기반 UI: 27개 목록·상세, 데스크톱/모바일, 증빙·연락처·사진, 확인 창, 상태별 버튼. 이것은 운영 계정으로 실행한 쓰기 검증과 다르다.
- 운영 DB: 모든 관리 리소스의 실제 조회 필드 및 전체 건수, 공개 검색 RPC, 새 심사 함수의 비권한 거부를 확인한다. 공개 URL과 로그인 요구 응답을 별도로 확인한다.

## 남은 제한과 필요한 후속 작업

| 항목 | 이유·영향 | 다음 작업 |
|---|---|---|
| 입양 상담·인계·신고 제재의 기존 API | 여러 DB 요청으로 처리하여 일부 저장 뒤 후속 기록이 실패할 수 있다 | 남은 업무도 트랜잭션 RPC로 이전하고 실패 주입 회귀 검사 |
| 제재 회원의 새 이의제기 | 일반 인증이 제재 회원을 거부하고 세션이 해제된다 | 이의제기에만 접근할 수 있는 제한된 본인 인증 경로 구현 |
| 이메일 실발송 | 발송 서비스 키·발신 주소·회신 주소 설정 필요 | 발신 도메인 인증 후 테스트 주소 수신 및 반송 처리 검증 |
| 실제 소셜 계정부터 운영 조치까지 | 브라우저 계정 인증과 테스트용 운영 자료가 필요하다 | 일반 Chrome에서 실제 로그인 후 승인된 테스트 자료로 검증. 현재 UI 테스트·격리 SQL 통과를 이 검증으로 간주하지 않는다 |
| 물품 편집·외부 결제·보호소 전송 | 조회 또는 의향 접수이며 외부 처리 계약/연동이 없다 | 실제 업무 정책과 외부 연동 후 별도 구현 |
| 이야기 샘플 | 실제 게시글 조회 뒤 기존 샘플을 덧붙이는 정책 유지 | 샘플 제거 여부를 별도 출시 데이터 작업으로 정리 |

숨김 이전에 이미 열린 화면 또는 진행 중이던 요청까지 소급해 제거하지는 않는다. 보호소 검색/메타데이터의 공공 원본 명칭은 유지된다.
