# 페이지 이동 지연 점검 · 2026-09-08

## 확인한 원인

- 운영 관심 친구 URL의 익명 요청이 약 2,040ms 걸렸다. 응답의 `x-vercel-id`는 `icn1::iad1::…`: 서울 진입점 뒤 미국 실행 서버를 사용했다.
- Supabase 프로젝트 설정에서 DB 위치가 `ap-northeast-2`(서울)임을 확인했다. 서버와 DB가 대륙을 왕복하는 배치였다.
- 인증은 세션 조회 후 회원 조회를 순서대로 실행했다. 페이지 데이터 조회는 그 뒤에 시작했다.
- vinext 1.0.0-beta.2의 route scanner는 페이지 폴더의 `loading`만 찾는다. 루트 `app/loading.tsx`만으로는 관심 친구의 DB 대기를 건너뛰지 못했다. 지연을 주입한 테스트에서도 응답이 막혔다.
- 마이페이지·함께하기·전체 메뉴·공통 목록 링크와 뒤로가기의 대체 경로에 전체 문서 이동이 남아 있었다.

## 변경

- `vercel.json`과 Nitro 함수 설정에 동일한 서울 리전 `icn1`을 사용한다. DB 이전은 하지 않는다.
- 기존 FK로 `auth_sessions → members!inner(*)`를 한 번에 조회한다. 토큰 해시·만료·세션 삭제·제재 검증은 유지하며 인증을 요청 간 캐시하지 않는다.
- 공통 로딩 화면과 주요 9개 경로의 로딩 파일을 연결한다. 관심 친구·나의 페이지·이야기·함께하기·동물 상세·이야기 상세·보호소 목록/상세·친구 찾기에 적용한다. 홈은 루트 로딩을 사용한다.
- 주요 내부 링크를 클라이언트 이동으로 변경한다. 공통 목록의 외부/API 링크와 로그아웃은 일반 링크를 유지한다. 전체 메뉴는 선택 후 닫힌다.

## 검증

- 자동 테스트 114개 통과: 지연된 DB보다 먼저 관심 친구 로딩 화면 스트리밍, 인증 조회 1회, 만료/삭제 세션 차단, 개인정보 응답 제외 포함.
- 로컬 Chrome에서 DB 응답을 보류해도 관심 친구 로딩 표시가 클릭 후 약 64ms에 나타났다. 이후 함께하기·전체 메뉴의 입양 안내 이동까지 문서 요청은 최초 1회뿐이었다. 브라우저 오류 0개, 메뉴 닫힘 확인.
- 홈 복귀 시 목록/위치 재요청 없음, 스크롤 복원, 오래된 목록 갱신 실패 후 재시도 검증 통과.
- lint·타입 검사 통과. Vercel용 빌드 성공 후 `__server.func/.vc-config.json`의 `regions: ["icn1"]`, `runtime: "nodejs24.x"`를 확인했다.
- 위 시간은 로컬에서 응답을 지연시킨 재현 결과이며 운영 속도 개선 수치가 아니다. 실제 서울 실행 및 운영 지연 시간은 배포 후 다시 측정해야 한다.

## 상태

로컬 수정이며 운영에는 아직 적용하지 않았다. 저장소 규칙상 명시적인 배포 요청 후 배포한다. 페이지별 데이터가 모두 즉시 준비된다는 의미는 아니며, DB 대기 중에도 화면 전환과 로딩 안내를 먼저 제공한다.

## 추가 개선: 미리 가져오기와 공개 페이지 분리

최종 자동 테스트 117개, lint, 타입 검사, Vercel 배포용 빌드가 통과했다. 생성된 함수 설정의 서울 리전 `icn1`도 확인했다. 브라우저 스트리밍 검증은 앞선 로컬 worker 빌드에서 통과했으며, Vercel 빌드 이후 재실행은 해당 빌드가 `dist/server/index.js`를 제공하지 않아 시작하지 못했다. 운영 배포 및 운영 환경 실측은 아직 진행하지 않았다.

- 하단 탭의 미리 가져오기를 활성화했다. 홈·함께하기는 전체 공개 화면을, 동적 페이지는 vinext의 로딩 화면을 미리 받는다. 최초 hydration 시 라우터 등록보다 Link의 관찰이 앞서는 문제를 재현해, 다음 프레임에 미리 가져오기를 활성화한다.
- 루트 레이아웃에서 `headers()`·`cookies()`를 제거했다. 메타데이터의 기준 주소는 운영 도메인으로 고정하고, 홈·함께하기는 `force-static`으로 선언했다. 회원별 페이지는 동적 처리와 서버 권한 검사를 유지한다.
- `ff_session`은 계속 HttpOnly 인증 쿠키다. 별도의 `ff_display_scope`는 기존과 동일한 비가역 해시로 화면 캐시만 구분하며 권한에 사용하지 않는다. 로그인 시 함께 발급하고 로그아웃 시 guest로 바꾼다. 기존 로그인은 no-store 표시 API를 한 번 호출해 이전하며 재로그인·DB 변경이 필요 없다.
- 관심 친구는 100개씩 동물 종류별 묶음 조회한다. 공공 동물 30마리는 동물 조회 1회, 230마리는 3회이며 저장 순서를 복원한다. 직접 등록은 게시 상태·재확인 기간, 공공 동물은 공개 뷰, 실종 동물은 active 필터를 유지한다. DB 실패는 빈 목록으로 처리하지 않는다.
- 로컬에서 다른 빌드가 동일한 dist를 교체해 중간 검증이 실패했다. 생성 파일이 존재하는 최종 빌드로 다시 검사한다. 임시 배포 복사본이 lint 대상에 들어가지 않도록 `.codex-local/**`를 명시적으로 제외했다.
- 브라우저에서 hover 없이 각 하단 탭의 선요청을 확인했다. 관심 친구 진입은 DB 응답을 보류해도 약 34ms에 전환 표시가 나왔으며, 선요청 단계의 회원 DB 조회는 0회였다. 실제 진입 시 인증 조회 1회, 전체 메뉴를 거쳐 이동해도 문서 로드는 최초 1회였다.
- 공개 HTML은 서로 다른 세션 쿠키로 요청해도 회원 DB 조회·세션 값 삽입이 없다. 첫 스트리밍 응답은 vinext가 렌더링 검증을 마칠 때까지 no-store로 보호하며, 배경 캐시 저장 완료 후 다음 요청은 s-maxage가 설정된 응답을 사용한다. 무조건 첫 응답부터 CDN 캐시되는 것은 아니다.
